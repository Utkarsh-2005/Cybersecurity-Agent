1. PROJECT OVERVIEW
--------------------------------------------------------------------------------
Project Name: PANDA (Multi-Agent API Security Assessment)

What it is: 
PANDA is an autonomous, multi-agent cybersecurity system designed to perform automated penetration testing on APIs. It uses a combination of deterministic network probing and advanced Large Language Model (LLM) reasoning to discover, analyze, and exploit vulnerabilities in web APIs without human intervention.

Problem it solves:
Traditional API security testing is highly manual, time-consuming, and requires expensive security experts. Automated scanners (like OWASP ZAP) only find basic, signature-based flaws (like missing headers or outdated software) but fail to understand complex business logic flaws (like Broken Object Level Authorization or Mass Assignment). PANDA solves this by using AI to actually "understand" what the API does, just like a human hacker would, allowing it to find deep logical vulnerabilities autonomously.

Main Objective:
To create an intelligent, orchestrated pipeline of AI agents that can automatically crawl an API, understand its business context, generate threat hypotheses based on the OWASP API Security Top 10, design safe test cases, execute them against the live target, and generate a professional security report.


2. TECHNOLOGIES USED
--------------------------------------------------------------------------------
- Core Language: Python 3.10+
- AI/LLM Frameworks: LangGraph (for multi-agent orchestration) and LangChain (for LLM interaction)
- AI Model: OpenAI GPT-4o-mini (accessed via OpenRouter API)
- Backend & Mock API: FastAPI and Uvicorn (for building the target vulnerable application)
- Real-time Communication: WebSockets (for live frontend updates)
- Frontend: HTML5, CSS3 (Apple-inspired UI), Vanilla JavaScript
- Data Validation: Pydantic (for strictly typing agent outputs and LLM JSON responses)
- Networking: Python `requests` library (for the execution engine)


3. PROJECT ARCHITECTURE & WORKFLOW
--------------------------------------------------------------------------------
The system uses a "Supervisor Pattern" via LangGraph. An orchestrator routes work to 6 specialized agents in a linear pipeline.

Step-by-Step Workflow:
1. Reconnaissance (Deterministic):
   The Recon Agent crawls the target URL, looks for OpenAPI/Swagger documentation, probes for hidden/undocumented paths (e.g., /admin, /api/v1), and captures baseline HTTP responses and security headers using different authentication profiles (e.g., user-token vs admin-token).

2. API Understanding (AI-Driven):
   The Understanding Agent takes the raw recon data and uses the LLM to infer the business logic. It identifies the data models (Users, Orders), sensitive fields (PII), and how the authentication mechanism works.

3. Threat Modeling (AI-Driven):
   The Threat Modeling Agent compares the API's behavior against the OWASP API Security Top 10 (2023). It generates ranked threat hypotheses (e.g., "The API might be vulnerable to BOLA on the /api/users/{id} endpoint").

4. Test Planning (AI-Driven):
   The Test Planning Agent designs specific, safe HTTP requests (probes) to prove or disprove each threat hypothesis. It defines exactly what payload to send and what the expected vulnerable/safe responses look like.

5. Execution & Analysis (Hybrid):
   The Execution Agent sends the planned HTTP requests to the live target API. It captures the real responses, and the LLM analyzes them to see if the vulnerability was confirmed, rejected, or if more testing is needed.

6. Reporting (AI-Driven):
   The Reporting Agent takes all confirmed findings, writes an executive summary, maps vulnerabilities to OWASP categories, provides remediation steps, and outputs a professional Markdown report, which is also rendered on the web dashboard.


4. MAJOR FEATURES
--------------------------------------------------------------------------------
- Autonomous Execution: Requires only a target URL and optional authentication tokens to run a full penetration test.
- Business Logic Testing: Capable of finding BOLA (Broken Object Level Authorization), BFLA, and Mass Assignment vulnerabilities.
- Live Web Dashboard: A beautiful, real-time UI that shows exactly what the agents are thinking, what HTTP calls they are making, and what vulnerabilities they are finding as they happen.
- Deterministic + AI Hybrid: Uses standard Python HTTP requests for reliable scanning, and LLMs for intelligent analysis.
- Built-in Vulnerable Target: Includes a custom "Mock API" purposefully built with OWASP top 10 vulnerabilities to demonstrate the tool's capabilities.
