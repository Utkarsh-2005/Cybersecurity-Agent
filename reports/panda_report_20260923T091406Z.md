## Executive Summary

This security assessment focused on a REST API that employs tiered access control through anonymous, user-token, and admin-token authentication profiles. The investigation revealed that while certain endpoints are protected against unauthorized access, significant issues were identified, including timeouts on critical endpoints and missing security headers. The API's response to attempts to access sensitive paths, such as the /.env file, was appropriately restricted, indicating some level of security awareness. However, the overall lack of documentation and the presence of 503 errors across multiple endpoints suggest that the API may be experiencing broader issues that could expose it to various vulnerabilities. Immediate attention is required to address these concerns and enhance the API's security posture.

---

## API Overview

The assessed API is a RESTful service designed to support a web application with varying access levels for anonymous users, regular users, and administrators. It includes endpoints for user management, authentication, and administrative functions. The API's architecture suggests a focus on role-based access control, but the lack of documentation and the presence of untested endpoints raise concerns about its security and reliability.

## Security Findings

### 🟠 F1: Potential Broken Object Level Authorization on User Data

| Property | Value |
|----------|-------|
| **Severity** | HIGH |
| **OWASP Category** | API1:2023-BOLA |
| **Confidence** | 85% |

**Description:** The API may not enforce ownership checks on endpoints that accept user IDs in the path, such as GET /users/{user_id}. This could allow unauthorized users to access sensitive data belonging to other users.

**Impact:** An attacker could potentially retrieve sensitive user data by manipulating user IDs in requests, leading to unauthorized data exposure.

**Evidence:**
- GET http://demo.owasp-juice.shop/users/2 with user-token resulted in a 503 Service Unavailable response.

**Remediation:** Implement strict ownership checks for endpoints that expose user data, ensuring that users can only access their own information.

### 🟠 F2: Mass Assignment Vulnerability in User Role Assignment

| Property | Value |
|----------|-------|
| **Severity** | HIGH |
| **OWASP Category** | API3:2023-Broken-Object-Property-Level-Authorization |
| **Confidence** | 75% |

**Description:** Endpoints such as POST /users may be vulnerable to mass assignment attacks, allowing users to specify roles or permissions in the request body without proper validation.

**Impact:** An attacker could exploit this vulnerability to elevate their privileges by assigning themselves admin roles or other unauthorized permissions.

**Evidence:**
- POST http://demo.owasp-juice.shop/users with user-token resulted in a 503 Service Unavailable response.

**Remediation:** Implement strict validation of request payloads to ensure that only authorized fields are accepted, particularly for sensitive operations like user role assignments.

### 🟡 F4: Information Leakage Through Login Error Messages

| Property | Value |
|----------|-------|
| **Severity** | MEDIUM |
| **OWASP Category** | API2:2023-Broken-Authentication |
| **Confidence** | 50% |

**Description:** The login endpoint may expose different error messages for valid and invalid usernames, potentially allowing attackers to enumerate valid usernames.

**Impact:** An attacker could exploit this vulnerability to identify valid usernames, facilitating further attacks such as password guessing.

**Evidence:**

**Remediation:** Standardize error messages for authentication failures to prevent information leakage and avoid revealing whether a username exists.
