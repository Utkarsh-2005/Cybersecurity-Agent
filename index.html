Agent workflow

Every agent runs on its own clock, reporting back to the orchestrator as work finishes — not a queue, a mesh.

The orchestrator (center) hands work out to whichever agent should run next; each agent reports its result straight back before the next hop — the moving dots trace that round trip on all six spokes at once, which is what makes the agents feel concurrent rather than a queue.

How this maps to LangGraph supervisor pattern

The hub-and-spoke shape above is the common LangGraph supervisor pattern: one node decides which specialist runs next, and every specialist routes back to that same node instead of to each other.

from langgraph.graph import StateGraph, END

graph = StateGraph(AgentState)

graph.add_node("orchestrator", orchestrator_node)
graph.add_node("recon", recon_node)
graph.add_node("scanner", scanner_node)
graph.add_node("threat_intel", threat_intel_node)
graph.add_node("risk_scoring", risk_scoring_node)
graph.add_node("remediation", remediation_node)
graph.add_node("reporting", reporting_node)

graph.set_entry_point("orchestrator")

# the orchestrator decides which specialist should act next
graph.add_conditional_edges(
    "orchestrator",
    route_to_next_agent,
    {
        "recon": "recon",
        "scanner": "scanner",
        "threat_intel": "threat_intel",
        "risk_scoring": "risk_scoring",
        "remediation": "remediation",
        "reporting": "reporting",
        "done": END,
    },
)

# every specialist reports back to the orchestrator, never to each other
for agent in ["recon", "scanner", "threat_intel", "risk_scoring", "remediation", "reporting"]:
    graph.add_edge(agent, "orchestrator")

app = graph.compile()
